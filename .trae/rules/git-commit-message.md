# Git Commit Message 规范

本仓库为 monorepo（`data` 为 git submodule），提交时 GIT MESSAGE 必须按项目**单独填写**，并在消息开头标注对应项目的前缀标签，方便按项目检索与回溯。

## 项目前缀映射

| 代码路径 | 项目 | 前缀标签 |
| --- | --- | --- |
| `app/admin/` | 管理后台（Nuxt 管理端） | `[admin]` |
| `app/web/` | 前台网站（Nuxt 官网） | `[web]` |
| `data/` | 数据仓库（git submodule） | `[data]` |
| 其余根级文件（如 `AGENTS.md`、根 `package.json`、`public/`、`graphify-out/`、`.trae/` 等） | 仓库根 / 工程编排 | `[root]` |

## 规则

1. 每个 Commit 尽量只针对一个项目改动；提交前先根据改动文件所在路径确定前缀。
2. 消息格式：`[项目前缀] 简述`
   - 示例：
     - `[admin] 修复设备管理页新增分支时 brands 未加引号`
     - `[web] 新增设备详情页相关路由`
     - `[data] 更新 ROM 数据`
     - `[root] 调整根级 dev 编排脚本`
3. 若一次提交确实跨越多个项目，需如实列出所有标签，如 `[admin][web] 同步前端接口与后台逻辑`；但应尽量拆分为多个提交。
4. `data/` 是独立 git 仓库，其记录更新需**两步提交、两次都纳入日志**：
   - 先在 `data/` 子仓库内提交，使用 `[data]` 前缀；
   - 再回到主仓库，提交子模块指针（gitlink）更新，仍使用 `[data]` 前缀，确保 `data` 的每次记录更新都反映在主仓库提交日志中。

## 判定流程

提交时按顺序判断改动文件所在路径：

- 命中 `app/admin/` → `[admin]`
- 命中 `app/web/` → `[web]`
- 命中 `data/`（含子模块指针更新） → `[data]`
- 其他 → `[root]`

一条消息默认只写一个前缀（除非确实跨项目）。
